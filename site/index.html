Methodology and limitations

Sources. Zaragoza City Council public data (bus stops and arrival predictions); Bizi GBFS, with a municipal station-data fallback if the provider is unavailable.

Bus routes. Each stop keeps the next arrival for every route separately. A stop is red if any known prediction exceeds 15 minutes; it is blue if all known predictions are at most 15 minutes. Stops without valid predictions are hidden.

Out-of-service bikes. Solo se contabilizan cuando la API publica el número de unidades fuera de servicio. Un valor ausente es unknown y nunca se transforma en cero. Para comparar bicicletas available y averiadas se utiliza el mismo conjunto de estaciones que informan ambos valores.

Coverage. Map requests cover visible stops at zoom level 12 or above, in batches with periodic refreshes. The total number of city stops is not the number queried or the number with predictions. Always consider query coverage before interpreting percentages.

Live versus historical data. Las gráficas en tiempo real reflejan el último estado obtenido durante la sesión. El histórico automático registra instantáneas cada 30 minutos (cuando GitHub Actions y las APIs estén available), conserva hasta 90 días y consulta una muestra rotatoria de hasta 60 paradas por ejecución. No representa un censo simultáneo de todas las paradas. Una espera de más de 15 minutos no prueba incumplimiento horario. Para cuantificar fallos crónicos se necesita almacenar series temporales y disponer de horarios programados.
